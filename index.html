The problem

Great products don't fail because ideas are missing. They fail when ideas don't become clear execution.

📧 Client Email

"We need users to invite employees and probably different permissions. Admin should control access and invitations should expire. Also maybe email notifications when someone joins. We'll figure out the details later."

❌ No acceptance criteria ❌ No edge cases ❌ No clear scope
BUSINESS REQUIREMENTS
Example Output
Business Objective

Allow administrators to invite employees into a shared workspace with role-based access control.

Actors
AdministratorInvited UserSystem
Business Rules
  • Invitations valid for 7 days by default
  • Invited user must accept before gaining access
  • Roles determine feature-level permissions
  • Expired invitations can be resent, not reused
Open Questions
  • Should expired invitations auto-delete or archive?
  • Can a revoked invitation be un-revoked?
  • Max invitations per workspace?
USER STORIES
Example Output
Team Management High

As an administrator, I want to invite a teammate by email and assign a role, so that they can access the workspace with the right permissions.

5 pts Ready for Dev
Team Management Medium

As an administrator, I want to revoke a pending invitation, so that I can prevent unauthorized access before the user accepts.

3 pts Ready for Dev
Team Management Medium

As an invited user, I want to accept an invitation and set my password, so that I can join the workspace on first login.

5 pts Ready for Dev
ACCEPTANCE CRITERIA
Example Output
Invite Teammate by Email
  • Admin can enter an email address and select a role from a predefined list
  • System sends an invitation email within 60 seconds of creation
  • Invitation link expires after 7 days (configurable)
  • Invited user sets a password on first login
  • Admin can see a list of all pending invitations
  • Admin can revoke a pending invitation at any time
  • Revoking an invitation invalidates the invitation link immediately
  • System prevents duplicate invitations to the same email
EDGE CASES
Example Output
EC-01

Invitation sent to an email already registered as a workspace member

→ System shows error, does not send duplicate
EC-02

User clicks invitation link after it has expired

→ Show expiry message with option to request resend
EC-03

Admin changes the role assignment after invite is sent but before acceptance

→ Role update applies; user receives updated role on acceptance
EC-04

Admin sends multiple invitations to the same email

→ System blocks duplicate; only one active invitation per email
EC-05

User clicks a revoked invitation link

→ Show clear message: invitation was cancelled

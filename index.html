GHERKIN ACCEPTANCE CRITERIA
Demonstration Output
Scenario: Admin invites valid new team member
  • Given an authenticated workspace administrator on Team Settings
  • When they enter a valid email and select role "Editor"
  • Then system generates a cryptographic 7-day single-use token
  • And dispatches a transactional invitation email within 60 seconds
  • And records the invitation in pending state on the admin dashboard
EDGE CASES & ERROR STATES
Demonstration Output
EC-01 · Duplicate Active Invite

Admin attempts to invite an email address that already has an active pending token.

→ Block duplicate; display "Invitation already pending. Resend instead?"
EC-02 · Expired Token Access

User clicks the invitation link 8 days after dispatch.

→ Show clear expired state with option to request a fresh invite from admin.
EC-03 · Role Changed Pre-Acceptance

Admin edits role from "Editor" to "Viewer" while invitation is pending.

→ Token maps to updated role on redemption; user enters workspace as Viewer.
